# ECO65-B 单条低速空载轨迹

2026-11-11 开发范围：在 `feat/v0.6-eco65-ubuntu-real-integration` 上新增显式受控入口。
设备接入、坐标和标定采用用户已确认的现场前提；不要求补交历史自动验收报告。
默认只读工作台保持原限制。软件停止不等同于硬件急停。

## 启动与现场顺序

在工程根目录运行现有环境，无需重新安装设备环境：

```bash
# 默认只读，不能运动
.venv/bin/python -m unloading_sim.workbench.ui

# 单独启动受控工作台，启动时仍不连接、不运动
.venv/bin/python -m unloading_sim.workbench.controlled.ui \
  --config configs/workbench/controlled.example.json
```

安装包也注册 `eco65-workbench-controlled`。已有可编辑安装未刷新时使用上面的模块命令。
原工作台布局、相机和真空观测继续保留，新增“受控执行”页。受控模式不加载回放作为实测数据。
运行一个受控会话；先断开其他工作台中的机器人观测连接，避免现场操作相互干扰。
真空板仍只有只读观测接口；本入口没有吸箱、阀门、输送带、自动卸箱或连续任务功能。

1. 保持现场已确认的空旷范围。在“受控执行”页点击“连接受控会话（不运动）”
   （“观测与检测”页保留同一连接按钮）。重复点击不会断开已建立的连接。
   机器人地址为 `192.168.1.19:8080`。连接只读能力/负载/限位，并临时把 UDP 反馈路由到本机
   `18089` 端口、请求 5 ms 周期；正常断开恢复原 UDP 配置。连接不会上使能、设置工具或发送轨迹。
2. 本次只读查询曾看到 `Arm_Tip` 的负载为 **0 kg**。现场人员需在控制器中选择/设置实际
   **1.5 kg 吸具负载**（额定 5 kg 是机械臂能力，不是吸具重量）。程序在每次提交前重新读取，
   仍为零或与 1.5 kg 相差超过 0.05 kg 时拒绝执行。不会擅自改写控制器工具参数。
3. 到“受控执行”页，点击“填入当前实测”，明确输入一个邻近关节目标。第一次现场试验可在
   人员已确认的方向将一个关节改动约 0.5°；每关节与起点差值上限 10°。
   填入按钮只复制当前位置，不会自动选择目标。未修改就规划会提示“目标与当前实测姿态基本相同”。
   当前 Pilz PTP 最小运动量为 0.001 rad（约 0.0573°）；至少一个关节差需超过该值。
   保持默认时间放大倍数 **10**。输入顺序是 J1、J2、J3、J4、J5、J6，界面单位为度。
4. 点击“从实测起点规划”，等待原生 MoveIt/Pilz 规划及最终发送路径检查完成。
   点击“查看轨迹预览”，拖动预览时间，并查看所选姿态的完整三维场景。
   预览不会运动；规划 JSON 不能作为执行输入导入。
5. 现场操作者点击“执行这一条”。程序重读实时关节；起点不符时撤销资格，必须重新规划。
   观察实测角度、指令角度、跟踪误差、距目标误差、反馈年龄及任务状态。
   发送计数只说明发送进度；`SUCCEEDED` 才表示实测到位及低速度持续证据成立。
6. 正常到位测试结束后，从新的实测姿态另选邻近目标，重新规划、预览并手动启动。
   在运动中点“软件停止”，等待 `STOPPING → CANCELLED`，核对反馈仍持续、实测速度降低并保持。
   不自动续跑原任务。若出现 `STOP_UNCONFIRMED`，现场使用控制器/硬件停止手段处理；
   程序保留未知状态与连接，不自动重连、复发或恢复任务。
7. 关闭窗口或断开会先处理本程序的活动任务。尚未确认停止时不直接关闭连接。
   默认只读工作台的退出仍只断开观测，绝不发停止命令。

本轮开发没有实际启动上述两次现场运动；正常到位、运动中停止及实机调度表现均为 **NOT_RUN**。
这不改变用户已经完成的设备接入与标定状态。

“填入当前实测”会明确显示读取中、成功及读取时反馈年龄。未连接、空反馈或反馈超过
100 ms 时显示原因并保留原目标，不再静默返回。此按钮只读关节；不会自动连接或运动。
切换机器人地址前需要先断开；误点其他地址不会破坏当前连接。

填入后直接规划曾因静止反馈的微小波动进入 Pilz，返回单个静止点（t=0.1 s），继而显示
`INVALID_TIMED_TRAJECTORY`。现提前提示无需运动，并区分“读取实测未完成”与“规划未完成”。
原生规划若仍返回少于两个点，也会明确拒绝，不补造时间点或签发执行许可。
尚未规划成功或目标已改动时，“查看轨迹预览”和“执行这一条”不可用。

## 现场模型、工具及版本绑定

配置 `configs/workbench/controlled.example.json` 引用当前本机的
`outputs/workbench/scene_snapshot.json`、`outputs/workbench/installation.local.json` 和
`configs/workbench/joint_mapping.json`。world 与 base_link 重合，相机随 link_1 转动。
关节目标不需要相机光学外参；不会读取 `training_extrinsics.example.json` 作为现场值。
保留原场景相对机器人底座的实际几何关系，仅作坐标表达转换，不移动布局或重生成箱堆。

当前模型保留 **715 个机器人/工具/支架碰撞几何、928 个环境/纸箱对象、12 个吸盘**，
箱体仍为 150×100×100 mm。保留官方机器人质量、惯量和关节限位。
新建的无接触检查上下文移除 2416 条仿真专用 robot/mast、link_3/tool 豁免，
无 payload attachment、无柔性吸盘/相邻箱接触豁免、无 J1 方向约束、无顶吸高度阈值。
仅保留官方相邻连杆、同一刚性工具/支架内部配对，以及来源中明确的固定安装接合面：
base_link/robot_mount_plate、link_1 安装座和法兰实际安装面。它们的几何仍参与其他物体碰撞检查。

吸具质量使用用户确认的 **1.5 kg**。COM 按 STEP 各实体的体积及质心加权，惯量按各实体
包围长方体加平行轴项估算，并写入新增固定工具质量链接。估算的法兰系 COM 约为
`[0.0002311, -0.0008289, 0.0895564] m`；完整有限正定惯量张量记录在轨迹包中。
**材料分布、COM 和惯量是明确标记的 CAD 工程估算，不冒称实测标定结果**，也不写入控制器。
空载仅指未抓纸箱，工具的质量、惯量和碰撞几何均不清零。

每条新轨迹绑定实际使用的 URDF/SRDF、全部引用网格 SHA-256、场景、安装配置、关节映射、
工具质量属性、执行配置、相关 Python 源文件和原生 worker 二进制版本。
不要求已缺失的旧报告/缓存；实际使用的网格仍必须逐个匹配来源哈希。
会话内许可校验摘要并单次消耗；修改目标/倍率、重连、输入文件变化或起点变化使旧许可失效。
历史 `PLANNING_ONLY_NOT_EXECUTABLE`、回放和预览 JSON 改标记不能得到许可。

## SDK、时间轴和监测语义

实地只读查询：Python/二进制 SDK **Robotic_Arm 1.1.7**，ECO65-BI/6 轴，第三代控制器，
ctrl `V1.7.0-1a610b9`，plan `V1.7.0-b34c631`，algorithm `1.5.2-0cabec5b`。
原状态查询 12 次延迟约 **4.2–10.4 ms**，因此不在 5 ms 发送循环中进行状态查询。
运行时核对该 SDK 和 V1.7.0 控制器系列，不兼容直接拒绝，无替代运动接口。
原参考 `zhangyong333/Unloading-Robot-Control-Platform@f0353d7` 此次访问返回 404，
无法重新审阅其中执行实现；保留已导入的只读片段，未继承“透传时暂停反馈”的做法。
本机 DuuQue 参考副本为仿真/标定工程，没有可复用的该 SDK 执行器。

- 原生 MoveIt/MTC 的 FixedState → MoveTo，Pilz PTP 输出真实 q/v/a/time_from_start。
  保留原始非均匀时间节点，以五次 Hermite 插值 q/v/a；时间乘倍率，速度除倍率、加速度除倍率平方。
  不把逐点 `rm_movej` 当作原生时间轴执行。
- 每 **5 ms** 调用 `rm_movej_canfd(degrees, True, 0, 0, 0)`：高跟随、纯透传、无拟合/滤波。
  内部弧度、秒。映射 J1—J6 顺序、符号、零偏移均显式逆变换；当前映射为同序、正号、零偏移。
- 在发送前检查插值多项式的全部位置/速度/加速度极值，离散指令差分与连续性。
  所有实际发送点均进入原生碰撞检查。额外采样密度由解析速度上界和完整模型的几何可达半径界
  确定，使相邻检查之间任意物体对的相对位移上界不超过 1 mm，小于 2.4 mm 检查间隙；
  原生检查还细分关节边。不会按数组下标把非均匀时间轴重新摊平。
- 时间使用单调时钟；最大发送迟到 2 ms、相邻发送最大间隔 9 ms、SDK 调用最长 2 ms。
  超限立即停止后续发送并请求软件停止，绝不集中补发积压点。不宣称普通 Ubuntu/Python 是硬实时系统；
  现场不能满足预算就故障停止，不能静默改成另一种运动方式。
- 独立子进程拥有发送循环、UDP 反馈接收和日志线程。GUI、视觉推理、规划、文件哈希不在发送线程。
  日志落盘在独立线程。反馈由实测 UDP 提供，界面显示其原始内核接收时间；不把动画或插值当实测。
  配置 UDP `joint_speed`，其单位为 0.01°/s；缺失时仅使用实测相邻角度差分并记录来源。
  控制器采样时刻未知，明确保留 UNKNOWN，不把接收时刻说成采样时刻。
- 连接时采集 2 s 实际 UDP 间隔，至少 100 个间隔且最大间隔 ≤50 ms；记录样本量、p95、最大值。
  这是执行监测准入条件，不能称为已测得恒定 200 Hz。GUI 约 10 Hz，原观测显示约 4 Hz，均不限制执行监测。
- 软件停止用**独立 TCP 通道**发送第三代 `set_arm_stop`，与 `rm_set_arm_stop` 同一控制器语义。
  不经过 SDK 全局锁或状态查询通道。`arm_stop:true` 只表示调用接受；继续用实际反馈确认停止。
  若停止时已有发送调用未返回，待调用返回后再次发停止，并丢弃此前的停止确认窗口。
  最长停止回复等待 0.5 s，停稳证据等待 2 s；无有效回复/反馈则停止未确认。
- 单任务、许可原子消耗、取消代数和独立停止信号防止重复点击，以及“停止发生在提交前检查期间”被吞掉。
  没有自动重连、报警清除、上使能、赶到起点或恢复旧任务逻辑。

参数为保守的本轮调试限制，不是机器人精度/制动性能认证：

| 项目 | 默认值 | 判断依据 |
|---|---:|---|
| 原生规划/发送速度上限 | 0.10 rad/s | 低于官方 3.14 rad/s，默认再时间放慢 10 倍 |
| 加速度上限 | 0.20 rad/s² | 本轮工程限制，默认缩放后再除 100 |
| 起点偏差 | 0.01°，内部 0.0001745329252 rad | 只容纳本次静止查询约 0.005° 的重复波动；超出必须重规划，不追起点 |
| 持续跟踪误差 | 3° 持续 0.10 s | 实测与对应发送时刻比较，超限停止 |
| 末点到位误差 | 每关节 ≤0.5° | 加上新鲜反馈和低速度持续证据 |
| 低速度 | 每关节 ≤0.5°/s 持续 0.4 s | 只使用真实速度/实际角度差分 |
| 反馈超时 | 0.10 s | 过期即停止，旧样本不能刷新证据 |
| 末点等待上限 | 5 s | 发送完仍未满足到位条件则停止并失败 |
| 停止确认上限 | 2 s | 超时锁定 STOP_UNCONFIRMED |

连接时读取控制器位置/速度/加速度限值。控制器限值必须包含已检查的本轮约束范围；
更窄则拒绝执行，不能扩大控制器限值来换取通过。

官方依据：[关节透传接口](https://develop.realman-robotics.com/robot/apipython/classes/movePlan/)、
[第三代 UDP 字段与单位](https://develop.realman-robotics.com/en/robot/json/udpConfig/)、
[第三代软件停止语义](https://develop.realman-robotics.com/robot/json/motionConfig/)。

## 记录与开发验证

每次提交创建唯一 `task_id`，保存到 `outputs/controlled_execution/<task_id>/`：

- `trajectory-package.json`：原始 MoveIt 时间点、缩放及最终发送点、碰撞采样、版本绑定和检查结果。
- `controller.json`：SDK/固件、查询延迟、控制器限位、负载以及实测反馈周期统计。
- `events.jsonl`：接收时刻、发送计划/实际/返回时刻、SDK 返回码、命令/实测角度、跟踪误差、
  抖动、停止请求/返回/确认及结果；单调时间用于同机时序，原始 UDP 保留。
- `task.json`、`result.json`：任务 ID 和最终结果。起点拒绝等发生在运动开始前的异常保留提交目录。

规划记录独立保存在 `plan-<id>/`，包含原生规划结果、最终路径检查和不可导入执行的预览文件。
假设备记录示例见 [fake record](examples/eco65_controlled_fake_record.json)，不代表真机验证。
