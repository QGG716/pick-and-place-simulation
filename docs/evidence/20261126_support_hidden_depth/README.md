# 2026-11-26 上箱“下方”范围延伸到隐藏深度（用户决定“按此规则来改”）

## 根因

现场任务 d5090aff 在 16:31 失败，当时 J1 = 73.7°。之前成功的几次 J1 都是 78.3°。相机装在 link_1 上，这次几乎正对箱垛，没有看到上箱的侧面，所以两只上箱的实测深度只有 0.001 m。

支撑判定的 C1 和 C5 要求接触点落在“上箱实测箱体的投影 + 3 mm”之内，深度方向就只剩 ±3.5 mm。下箱的接触点其实看到了（687 / 1721 个），但都在上箱正面后 6–16 mm，中位数 13–15 mm，于是全被排除，只剩 0 / 26 个，不到要求的 30 个。结果下箱没被认成支撑，它补出来的体积挡住了两个目标的包络，导致规划前就被拒绝（`GEOMETRY_UNCERTAINTY_BLOCKED_AT_REST`）。

而且 C1 不通过时代码是静默跳过的，不留原因，界面上只看到一句笼统的“没有下箱满足支撑规则”。

## 改动（`stack_support.py`，确认叠放和通用静置接触两条规则共用）

- `under_upper_footprint`：
  - 横向：仍是实测宽度 + 3 mm。
  - 深度方向（和观测面法向最接近的那个水平轴）：从上箱正面（外扩 3 mm）往里，一直到上箱包络的隐藏深度上限。这个上限就是碰撞检查已经在用的最大 0.2 m 补全。
  - 上箱没有观测面法向时，回退到原规则。
- 高度窗、30 点下限、C2 到 C7、支撑平面、0.4 mm 支撑穿入限制、接触权限范围：都没有变。
- 修改了 11-20 的规则“只用上箱实测投影 + 3 mm”（只改深度方向）。
- C1 不通过时记录 `INTERFACE_POINTS_BELOW_MINIMUM`，带接触点数、要求点数和所用的投影范围。
- 支撑记录里新增 `footprint` 字段。
