# 2026-11-27 基于 TCP 的相机外参重新标定：算法与操作界面

来源：用户请求“重做一次标定，你在‘坐标、TCP与场景’标签页里把操作界面写好，再写好基于TCP的标定算法，都弄好后要我来执行”。

## 求解对象

相机装在 link_1 上，求 `Y = T_link1_camera_optical`，用法不变：`T_D_optical(q) = T_D_link1(q) @ Y`。
参考量是机器人自身的 FK；本界面只读图像和关节角，不发任何运动或阀门指令，机械臂由操作员用示教器点动。

两种采集方式（`single_carton/tcp_calibration.py`）。

**现场更正（同日）**：相机光轴和手臂所在竖直平面在水平方向上相差约 90°，并且相机随 J1 一起转，所以装在吸具上的板永远进不了相机视野。现场改用触点方式作为默认；手眼方式只保留给能看到吸具的安装。触点方式新增：
- **尖端自动求解（四点法 TCP 标定）**：同一角点用明显不同的吸具姿态触碰 ≥ 3 次（建议 5 次，前后左右各倾斜 20–30°），线性解出尖端在 link_6 下的坐标。尖端可以是临时固定在吸具上的任意硬尖，不用拆吸具。
- **多板位**：板可以换位置再做一组，每个板位各有一个位姿。
- **联合优化**：相机外参、各板位位姿、尖端坐标，对全部角点重投影（px）和全部触点残差（mm）一起做 Huber 拟合。
- **新增检查**：每个板位触点 ≥ 6、不同角点 ≥ 4；尖端姿态分散度（相对转动向量的第二奇异值）≥ 10°；尖端坐标标准差 ≤ 1 mm。
- **界面**：默认触点方式；尖端填“自动”；“换板位置”按钮；每次触点后显示该角点的姿态分散度；选中的角点在实时画面上用红圈标出（角点顺序按当前画面判定，与求解用同一规则），另有“角点示意图”。

合成验证：两个板位、尖端未知（真值 [31, −54, 262] mm）、触点噪声 0.4 mm、5 张照片，尖端误差 < 1.5 mm，外参误差 < 3 mm、< 0.15°，全部检查通过；没有同一角点的多次触碰时拒绝自动求尖端（`CALIBRATION_TIP_NEEDS_PIVOT_TOUCHES`）。


- **BOARD_ON_TOOL（仅当相机能看到吸具）**：标定板刚性固定在吸具上，位置任意。每个静止姿态 i：
  `A_i = T_link1_tcp(q_i)`（FK × 现场工具 TCP），`B_i = T_camera_board`（平面 PnP：IPPE 候选 + LM），
  满足 `A_i X = Y B_i`，`X = T_tcp_board` 一并求出。
  - 初值：两两 `AX = XB`（Park–Martin 旋转 + 最小二乘平移），`Y` 用 SO(3) 弦均值；
  - 精化：`Y`、`X` 对全部标签角点的重投影误差联合优化（Huber 1 px）。
  - TCP 数值本身的误差不进入 `Y`（由 `X` 吸收）。
- **TIP_TOUCH（推荐，现场用这个；也是上次现场的方法）**：标定板固定在场地，已知尖端（link_6 坐标，默认历史探针 `[0, 0, 0.07]`）依次轻触板上角点，Kabsch 得到板在 base 下的位姿；再在任意 q 拍照，求 `Y = inv(T_base_link1(q)) T_base_board inv(B)`，最后对全部角点重投影精化。

板的角点顺序约定（检测器的角点 k 对应板文件的哪个角）每个会话用图像判定一次：8 种约定中 PnP 中位误差最小的那种，而且必须明显优于第二名。上次现场用的 5×5 AprilGrid（80 mm，`DICT_APRILTAG_36h11`，2 位黑边）的角点按逆时针列出，即印刷面朝板坐标 −Z，已自动识别。

## 检查项（实施者取值；1°一致性和 3 mm 触点容差沿用上次现场标定的设置）

| 检查 | 限值 |
|---|---|
| 可用样本（手眼 / 触点照片） | ≥ 8 / ≥ 3；每张 ≥ 16 个角点；触点 ≥ 6 |
| 总重投影 RMS | ≤ 0.8 px；单张 ≤ 1.5 px |
| 留一预测最大误差 | ≤ 2.5 px |
| 单张一致性 | ≤ 20 mm、≤ 1°（单张 PnP 的深度噪声在 1 m 时约 7–14 mm，所以平移放到 20 mm；联合解由留一和标准差把关） |
| 外参估计标准差 | 平移 ≤ 2 mm，转角 ≤ 0.2° |
| 姿态转动多样性（手眼） | 相对转动向量第二奇异值 ≥ 15° |
| 触点配准 RMS | ≤ 3 mm |
| 采集静止 | 点击前、点击后新帧之后两次关节读数相差 ≤ 0.02° |

任一项不通过就写成 `extrinsics.rejected.json`，不能生成现场配置。另外附一项不参与判定的深度诊断：标签中心处 D435 深度减去几何预测的中位数（用来判断深度是否有系统偏差）。

## 输出

`<record_root>/calibration/<会话>/`：`session.json`、`samples/`（PNG 原图、深度 .npy、q 与静止证据）、`extrinsics.json`（`schema=eco65_tcp_camera_extrinsics_v1`，`status=SOLVED_REQUIRES_VALIDATION`，可被 `Extrinsics.load` 加载）、`report.json`、`overlays/`（绿=检测角点，红=残差放大 8 倍）。与当前外参的差别（平移、绕光轴 x/y/z 的转角、1 m 处点的移动量）写进结果和界面。

“生成使用新外参的现场配置”只写一份配置副本（`camera_extrinsics` 指向新文件并记录依据）；运行中的程序仍用旧外参，用新配置重启后才生效。
