## 复现与根因

原第五步报告含机器人过期；新增严格探测在未优化生产代码上再次失败：
12 秒稳定窗口只收到 10 条世界快照，机器人过期 7 条、机构过期 5 条。

## 最小修复及保留的规则

`replay_cache.py` 与世界节点只在显式 replay 模式复用内容：

- 第一条仍走完整领域/算法/来源校验。后续对比实际全部 ROS 不变字段，包括所有 cargo JSON、来源、未知区域和静态 coverage，
  仅排除明确的传输序号/发布时间字段；不是信任 observation_id/run_id。持有自有副本，调用者修改旧消息不会污染缓存。
- 重复传输仍检查双表示时间、完整回放封装及 source epoch/sequence/restart 守卫。
  同 session 不变内容发生任何变化（也包括原始 JSON 字节格式变化）会拒绝；有效新 session 经完整校验和守卫后替换记录并清缓存。
  世界中的采集记录保持首次接纳的版本，传输 publication guard 单独前进，独立世界心跳表达当前活性。
- 最多保存 8 个已验证的世界模板，键含真实机器人/机构内容、当前时间故障/过期原因和 world frame。
  每次提交先按真实最新接纳的源采样重新判定年龄和锁存故障，再查模板。
  状态内容或故障变化走对应模板/完整组装；模式参数仍只读，默认 online 路径不使用模板。
- 领域对象只在实际机器人内容完全相等时共享已冻结场景，替换已经校验的机器人采样元数据。
  全部领域 JSON 字段保留，只更新其中的小型机器人 revision；ROS 外层也使用同一真实采样。
  CPU 回归比对其与完整构造/序列化的等价性，并拒绝内容变化。
- Marker 仍通过原生产 renderer 每次生成，包括故障文本、删除 tombstone、原始坐标与晚订阅。
  没有缓存旧的故障显示，没有缩小消息，没有改 DDS 类型、线程模型、输入速率、0.1 秒 watchdog 或 0.5/2.0 秒阈值。

稳定窗口世界端机器人/机构回调各 120 次，入口年龄最大 0.03598/0.03620 秒；
重复感知回调 p50/max 0.00133/0.00211 秒；模板复用 0.00094/0.00249 秒；
Marker 生成 0.02597/0.05701 秒；DDS 世界 publish 0.00748/0.01173 秒。
完整静态感知发布仍是原频率/原路径，并未降低频率来隐藏问题。
最终实际序列化大小：感知 2,472,932 B、世界 4,924,744 B、Marker 178,969 B。
与原报告字节数的小差异来自传输元数据和故障文本；不是字段裁剪。
