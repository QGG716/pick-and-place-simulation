## Actual integration and safety boundary

`LayoutTrajectoryConnector._finish_place_branch` keeps the receiving pose and
existing IK candidate stream. Its optional `_connect_pose(fixed_endpoint_backend=?)`
connection uses the chosen q goal directly with V2 `plan_cspace(goal_js,start_js)`.
It does not convert q goal into a new unconstrained pose target. Without the
adapter the original connection remains selectable. With the adapter there is
no CPU fallback and no prerequisite CPU TRANSIT solution.

The adapter owns the full extraction-end ? pre-place interval. Grasp/cup choice,
contact, support release, extraction, placement, receiving, withdrawal and runtime
physical stopping retain their existing implementations. Full-task and execution
implementation fingerprints include the new modules to invalidate stale bundles.
The hook itself was covered by a directed mock control-flow regression; a complete
single-box call through this hook has not succeeded or been physically tested.

`run_stage` checks endpoints, order, bounds, native timestamps and derivative
limits, then invokes the existing exact `_path_failure` on every proposed
joint-linear edge. The POC subdivision is the production edge checker, with its
conservative displacement bound (up to 1.25 mm per fine sample); this is discrete
edge validation, not mathematical continuous collision detection. Rejected
candidates consume finite attempts and continue; identical rejected q paths are
not repeatedly validated. Revision/cancel/deadline gates run before and after
native calls and before acceptance. No implicit deadline is imposed.

The native B-spline output conversion uses the pinned API's trimmed evaluated
trajectory. It has not yet been exercised on a successful GPU output in this
layout. Native dq/ddq are retained as native evidence, not represented as the
controller derivative of a different interpolation. Retiming/smoothing is still
subject to the existing final replay gate. `authority_accepted`, `delivered` and
`isaac_execution_completed` remain distinct. No new executable bundle was issued.

The worker is serial, persistent for an identical context, and drains on close.
Scene/model/attachment/policy changes rebuild it and retain the generation/reason.
The first implementation uses explicit full rebuild, not partial obstacle updates;
it cannot silently exceed a preallocated scene capacity. Cancellation is logical
result discard after synchronous compute, not kernel interruption. Hung native-call
recovery and a live online-scheduler bridge were not implemented.

## Isaac outcome and remaining work

`isaac_result.json`: `BLOCKED_PLANNING`, **0 physical trials, 0 stage replays,
0 completed boxes, no new video**. Model kinematics/inertials pass, but neither
GPU fixture yields a candidate for final authority acceptance. The precondition
for the one authorized new-world 640?360/5 fps/1? full cycle was not met. Runtime

The first remaining blocker is a usable collision representation with exact,
owned assembly permissions and sufficiently tight outward coverage, while
retaining the final authority. Next come a genuinely accepted full-business
GPU candidate, successful-output/time conversion validation, full-task final
retiming validation, and then the single new-world physical trial. Advanced
scene-update performance, robust hung-worker recovery, cross-backend wire
alignment and online scheduling are unverified. Full torque constraints and
machine certification remain separate. Current evidence supports fixing model
representation first; it does not support ranking GPU vs CPU or the other backends.
