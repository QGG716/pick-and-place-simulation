# S50 真实表面与运行时碰撞诊断

本轮读取同一份 S50 STEP（SHA256 `7296244abc02bca236a7ed26a0f10f5cc56fc63b7381fc1293b2edbb92509bc3`）、七个原始部件网格和两张独立修补面。源资产没有删除三角形、加厚、缩放、填凸包或改动环境；运行时加载器的三角形数量差异单独记录，不能声称加载后逐面原样。局部 CAD 修补证据及 J1 BRep 内壳问题保持原记录；BRep 检查状态不阻断对真实三角表面的 Coal 查询。

## 安装面离散误差的具体来源

新增 `tools/audit_s50_base_support.py` 对原 STEP 作只读检查，并在内存中重现历史转换参数（线偏差 0.10 mm、角偏差 0.15 rad）。

- 真实安装支承面为 CAD Y = −0.003 m；原 CAD 全部拓扑顶点的最低差约 −2.91e−17 m，计算包围界最低差约 −1.00e−10 m，后者对应 OCCT 数值精度量级。
- 原 base OBJ 只有顶点 **14085** 低于该面超过 0.1 nm，坐标 `[0.14679515, -0.00300054, 0.05360862] m`，低差约 **0.540000 µm**。
- 按原转换参数可在 CAD **face 137** 再现该离散节点；再现点与已发布 OBJ 点相差 **2.1566 nm**，没有修改原文件。
- 对完整原 CAD base 和六张真实支承面分别作最近距离查询：最近点位于 **face 19**，为 `[0.14679515, -0.003, 0.05360862] m`，距离约 **0.540000 µm**。
- 不能以 face 137 的最大边容差解释并放行所有低点：该离散点到 face 137 最近边距离约 **1.406 µm**，超过该边自身约 **0.555 µm** 容差。报告如实保留 `local_tolerance_qualification_passed: false`，没有把全局最大容差写成安装碰撞许可。

可提交源证据为 `assets/robots/huayan_s50_2000/generated/mount_contact_source.json`，包括 STEP、原 base OBJ、link-local base OBJ 和测量文件哈希，以及该单个顶点的索引、坐标、最近点和逐面/逐边距离。它识别的是固定源文件的离散偏差，不是允许移动整个机器人、对整条底座免碰撞或允许新的穿透。安装支承范围和全部其他碰撞仍需独立运行时核验。

## Coal 诊断输出契约

执行命令：

```sh
python tools/diagnose_s50_runtime_collision.py --output outputs/s50_task_collision_20261111
```

可先用 `--pose cad_q0` 跑一个明确诊断姿态。默认有限集合为 CAD 零位、六轴分别 ±0.35 rad 和两个确定组合，共 15 个姿态。可另用 `--pose mount_probe_j2_2p0`、`mount_probe_j2_2p4`、`mount_probe_j2_2p8`、`mount_probe_j2_3p0` 查询向下折叠时活动连杆与支座的关系；这些角度仍只是 CAD 显示诊断，未宣称机械限位合法。

`--mount-cases-only --output outputs/s50_task_collision_20261111/mount-cases` 单独运行安装接触三类测试：正常源安装；诊断副本向下偏移 1 mm 的负面样例；J2 有限折叠姿态中的实际活动连杆/支座碰撞。最后一类按 2/2.4/2.8/3/π rad 查询，保存每次结果，只有实际检测到活动连杆碰撞才选中；无碰撞就如实留下诊断缺项。这些测试只在独立诊断副本中改变姿态或安装矩阵，不是调整任务布局。每个样例保留原始 Coal 结果，并另外记录有来源约束的支承面接触证明，许可集合必须始终不含活动连杆。

`runtime-collision-report.json` 的 schema 为 `s50_runtime_collision_diagnostics_v1`。输出包括完整 40 箱身份、冻结环境指纹、物理安装面与模型基准矩阵、固定初始横带高度、每姿态 q/真实连杆 FK、全部碰撞 shape 对、原始 Coal 距离、碰撞标志、最近点、接触信息、肘/腕明确连杆并集相对安装轴的水平包络及横带最小距离。每姿态另存 JSON，完整报告另有 SHA256 文件。

原生距离的负值原样保留；它可能是相交哨兵，不能冒充穿透深度。相交时即使 `contacts` 为空仍记录碰撞。只有分离对、有限最近点且点间距与返回距离一致时，`nearest_points_valid` 才为 true；查看器只应绘制经过此检查的最近点线。

直接查询全部九张 shape 的 36 个自身对和每张 shape 对全部环境实体，**不使用相邻关系自动免碰撞**。同一刚体所属的补片对、相邻机构接口对、非相邻连杆对分别标注。CAD 自身存在相邻接口接触并不能证明应排除所有相邻连杆；当前证据也未给出 S50 腕部与现有吸具的物理归属，因此工具未安装，腕部例外为空。全部接触记录属于诊断证据，碰撞数不代表任务成功或失败。

本轮源码测试覆盖开放/闭合表面、重复/退化/非流形三角、绕序错误、分析量化不改源几何、空 contacts 的真碰撞、负距离与非有限最近点，以及后端异常不能被距离结果掩盖。实际服务器运行结果由本轮独立输出目录保留；本说明不提前声明运行时碰撞、正式初态或卸箱规划通过。

## 场景遗漏修正与实际加载差异

首轮 16 个姿态的服务器报告仅传入 `fixed_components + cartons` 共 49 个对象，漏掉耦合升降机构的 99 个实体，而且横带斜切实体被当作其外接 OBB。该轮 7,632 次查询保留为**不完整场景诊断**，不能作为完整场景通过证据。旧摘录 SHA256 为 `f42919ab9cca1bd320ddc2b3bd839491ce6c911daab6dc840deb5fa96c7e3f10`；其固定底座与安装支座的独立三情形测试不涉及这些遗漏对象，适用范围仍仅为该对象对。

修正后的入口通过 `coupled_conveyor_state(layout, 0.6, cartons)` 取得完整 148 个实体，包含 40 箱。初始耦合场景指纹为 `319e091c0924be0ec730724f123f2c2c8d08150ca2087652adcdf6b222f6a206`。回归逐项核对全部对象身份、尺寸、位姿和实体定义；横带保留原 8 顶点的斜切六面体，用 12 个三角面构建 Coal Convex，其余 147 个对象使用冻结工程中的 Box 定义。未知实体类型报错，不退回外接盒。这里的几何真实性限于工程已有定义，未追加真实机构孔洞等未建模细节，也不宣称 CAD 机械实体全面合格。修正后的 16 姿态实际完成 21,888 次 shape 对查询，结果见下节。

首轮实际 Coal 读取的九张网格顶点数量全部与源文件相同，但 base/J3/J4/J5/J6 的三角形分别由 92,180/335,732/121,916/122,252/26,286 变为 92,164/335,698/121,914/122,250/26,284；J1、J2 及两张补片数量不变。合计少 56 个三角形，各连杆数量差恰与源审计的零面积三角形数一致。这是数量层面的对应，尚未用逐面索引差集证明每一删去面均为那一零面积面。原始资产和源审计保留不变，报告不将加载数量相等或数量差解释为完整表面覆盖证明。
