## 逐三角加载审计

新增入口：

```sh
/opt/planning-venv/bin/python tools/audit_s50_loader_triangles.py \
  --output outputs/s50_mount_entry_20261111/loader-audit
```

工具直接读取实际 Coal 碰撞体的 `vertices()` 与 `tri_indices(i)`，核对源 OBJ SHA、物理 link、加载路径和单位缩放。源数值或精确的 float64→float32→float64 往返必须与实际坐标的唯一值多重集完全相等，才建立显式双向顶点置换，继续核对有向顶点索引。不使用近邻配准或放宽数值容差；量化后重复坐标导致顶点身份有歧义时明确拒绝。三角形按转换回源顶点编号的三元组及重复出现次序逐项匹配，允许有记录的角点循环起点变化但不允许翻转绕序，保留双向原始面索引映射；每个丢失面记录源索引、三个顶点、加载后对应索引/坐标及两侧面积。重复的非零面被删、绕序变化、非零面在量化后退化以及无法解释的坐标变化均不能得到“源零面积面对应通过”。

实际数组及完整映射保存为服务器 NPZ 并在报告中绑定 SHA；原文件不修改。12 项定向回归已通过。首轮服务器读取九张真实网格耗时 29.4117 s，均因“原顶点数组同序”假设不满足返回 `UNEXPLAINED_VERTEX_CONVERSION`，退出码 2；[首轮记录](loader-first-run.json) 和服务器原始数组保留。该结果没有完成三角对应，不能把未审计的删除计数 0 当作零差异，也不能把按旧索引比较的坐标距离误写成物理几何偏移。

增加精确唯一坐标置换后的[第二轮真实记录](loader-permutation-run.json)，SHA256 为 `98d1ab780e3949ad9c6a1a2961da6585ccd594b88b83071ca653f7e635bf1b66`，耗时 29.1648 s，仍退出 2。仅 `s50_link_1_1`（J1 局部补片）确认了全部 1,025 个顶点的 float32 往返与精确置换，以及 1,023 个三角形的原始索引对应；该补片本身没有零面积面，也没有删除面。其余八张网格仍为 `UNEXPLAINED_VERTEX_CONVERSION`，未进入逐三角对应阶段。实际源总数 1,314,722 与加载后 1,314,666 相差 56，但**这 56 个删除面与源零面积面的逐项对应仍未完成**。未用猜测的浮点误差阈值制造通过，也不把补片通过扩展为完整模型通过。

后续最小调查应先针对一张失败网格中的一个未对应顶点，保留原 OBJ 数值文本、实际导入器版本/选项、导入后的数值及 Coal 顶点和索引，定位差异在哪一次解析、数值转换或重排中产生；现有服务器 NPZ 可以用于离线对照。只有得到可复现的转换证据后，再对该网格全部坐标严格核验并继续三角映射，不用反复扩大容差代替来源证明。本次按“先推送当前结果”的要求停止扩大调查。该问题独立于 J1 残余 BRep 壳结构和任务准入；无论日后加载对应是否通过，都不自动代表连续实体表面或整机碰撞资格合格。
