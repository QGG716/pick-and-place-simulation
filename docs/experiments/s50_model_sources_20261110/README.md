## 保留的失败和资料冲突

J1的原始BRep拓扑检查失败；J1面74、J2面75未三角化，各自有符号面积约-1.292529 mm²。实际执行 `ShapeFix_Shape.Perform` 后未改善，边界尺寸不变，七份网格SHA与原始导出完全相同。未删除这些失败、未把缺口当作不存在，也未将显示成功等同于碰撞合格。

[中文规格页](https://www.huayan-robotics.com/s)与[英文规格页](https://www.huayan-robotics.net/s-heavy-payload-collaborative-robot)同列6轴、50 kg载荷、156 kg整机质量、2000 mm臂展。网页速度J1–J6为180/120/120/180/180/224 °/s，机械手册PDF65为244/150/120/180/180/180 °/s；J1/J2/J6存在冲突，未静默选取某一组作为本CAD的验证通过速度。

关节范围两来源一致：J1/J4/J5/J6为±360°，J2为−190°至+10°，J3为±160°。范围是控制器坐标定义下的数据，不能在缺少零位映射时直接套到任意 CAD 六轴角度。

尚须取得可核验的六轴控制器零位/正向及其参考姿态、安装基坐标绕轴定向、法兰/tool0及现有吸具的物理对应、速度修订适用性，并解决两处缺面的完整碰撞覆盖。逐连杆惯量与力矩另列为动力学缺项，未复制FANUC数据，也不因50 kg载荷小于现有工具与箱体总质量而中止几何资料工作。

最能补足当前缺项的资料是厂商 S50-2000 对应版本的 URDF/DH与坐标系说明，或带六轴角度和正向定义的官方零位参考姿态；还需能确认工具安装关系的机械接口图。只增加外观图片不能解决这些缺项。

## 发布传输形式

GitHub连接接口对部分约13 MB的OBJ文本文件重复返回HTTP500，其他来源文件可正常上传。本轮将7份OBJ以无损gzip形式提交，原始OBJ只在本地保留并可从STEP转换或运行 `pack_meshes.py --unpack` 恢复。

压缩脚本固定gzip头时间为0、文件名为空；每个文件核对原始与压缩SHA256、字节数，并验证重复压缩一致、解压后逐字节等同原始OBJ。完整记录在 `assets/robots/huayan_s50_2000/derived/compressed_meshes.json`。`cad_audit.json` 的原始路径、原始SHA256和全部几何检查结果保持不变。此变更只解决传输，未使用网格简化或修改几何；两处缺面及模型未就绪结论仍保留。
