## Implementation and dependency scope

- Geometry schema is now `curobo_geometry_v3_robot_local_cover`. The cache stores
  only robot sphere geometry, fitting settings, quality and mesh provenance.
  Its key covers mesh hashes/transforms, algorithm schema, fitting parameters,
  pinned cuRobo commit and seed. Old full-configuration cache records cannot load.
- `prepare()` always rebuilds robot/runtime configuration, current permissions,
  limits and attachment inertials. Policy revocation cannot resurrect cached
  self-collision exemptions. Outer worker keys cover complete configuration and
  request dependencies, excluding only per-solve endpoints/ID/deadline/cancel
  and redundant snapshot/FK reference data.
- Official robot collision meshes still use MORPHIT (64 requested spheres,
  100 iterations). Mesh vertices plus 20,000 surface samples assign uncovered
  points to their nearest sphere. Only those spheres grow; no fitted sphere is
  shrunk. This replaces one worst gap being added to every sphere of a link.
- All 202 physical tool parts and the held carton use full OBB solids on CUDA.
  Sphere/OBB SDF and 15-axis OBB SAT constraints cover faces, edges, corners,
  thin plates and volume. No payload or rigid insert was removed.
- SAT separation is a conservative lower bound on Euclidean separation, not
  exact distance. A GPU AABB lower bound rejects only provably distant pairs
  before narrowphase. Some diagonal near-clear cases may still overreject.
- Project-owned `PairCollisionCost` participates inside native optimization,
  graph/sample feasibility, constraints/metrics AND interpolated output checks.
  Native robot self-collision remains active. Dynamic CUDA tensor broadphase
  requires `use_cuda_graph=False`; CUDA planning itself remains enabled.
- The pinned `SolverCore.get_all_rollout_instances()` omits
  `additional_metrics_rollouts`. Explicitly installing the same cost in the
  interpolated rollout fixed a second rejection after optimization was feasible.
- The exporter previously used uncompressed cups. The existing CPU authority
  already models 10 mm nominal cup compression. `authority_tool` now exports
  that exact current geometry. Original uncompressed tool source/request identity
  is retained. Rigid dimensions and the compression allowance were not changed.
- Native endpoint rejection after authority acceptance returns MODEL_MISMATCH
  with `NATIVE_COLLISION_REJECTS_AUTHORITY_ENDPOINT` and pair diagnostics, never
  physical START_INVALID. Missing graph seeds and native optimization failures
  have explicit first causes; finite authority-rejection continuation remains.

Pinned source files, hashes and supported interfaces are recorded in
`upstream_source_review.json`; local and installed source hashes match. The
installation is an archive source tree with PINNED_SOURCE.json, not a git checkout.
This commit has a single clip_plane fitting option, but that is not a complete
six-face OBB pair representation. No clipping was used to remove physical volume,
and no latest-documentation parameters were borrowed. The extension uses pinned
internal cost-manager interfaces; version upgrades require revalidation.

receive no automatic contact permission. Unknown base/wrist ownership mappings
fail configuration. Rigid tool/payload pairs no longer inherit zero-gap robot-self
semantics merely because they are attached to the kinematic chain.
